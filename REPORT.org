** エグゼクティブサマリー

satori-html は 2022-12 を最後にリリースがなく（最終 commit 2025-04 は依存更新のみ）、14 個の open issue を抱えたまま ~130K weekly downloads で使われ続けている。実証の結果、satori-html@0.3.2 は **Bun 上ですべての入力でクラッシュする**（useObjectSyntax 時に常時注入される =:where([style])= セレクタが bundled parsel をクラッシュさせる）ことが判明し、rewrite の必要性は決定的。唯一の活動的な fork（@xevion/satori-html）は Bun 問題を回避する代わりに =url(a;b.png)= パースをリグレッションさせている。

komeiji は htmlparser2 + css-select + css-what + style-to-object を採用（実装案 A–E 比較の結果 B）。komeiji 自身のコードは ~300 行（最大ファイル 95 LOC）で、parser correctness の長尾リスクを実績ある実装に委譲する。テスト 64 本（上流互換 + 改善分 + satori-html リファレンスから取得したゴールデン SVG とのバイト等価比較）がすべてグリーン。

* 調査軸別の発見

** 軸 1: satori 要素契約（satori@0.33.4 一次ソース + librarian 交叉確認）

- プレーンオブジェクト ={type, props}= を受理。=isReactElement= はプリミティブ除外のみで =$$typeof= を要求しない（src/utils.ts）
- children は =props.children=。=normalizeChildren= が =flat(Infinity)=、null/undefined/boolean を drop、数値を文字列化、隣接文字列を連結 → **children 配列の undefined ホールは satori が drop する**
- HTML 要素で =class= / =className= は無効。消費されるのは =style= / =children= / =tw= / =lang=（src/layout.ts）。=props.tw= は twrnc 経由でネイティブ Tailwind 処理
- style は camelCase が標準。kebab-case も css-to-react-native の =camelizeStyleName= 経由で許容
- satori 本体は HTML entity をデコードしない → tree provider の責務（satori-html#20 で確認）
- タグ whitelist なし（未知タグ = 汎用 flex）。=img= は特別扱い、=\<text\>= は throw

** 軸 4: style 文字列 → camelCase オブジェクト

- style-to-object v2.0.2（2026-07, 45.9M DL/週, dep = inline-style-parser のみ）: kebab キーで出力（camel 化しない）。=top:= / =:12px= / =;= → null、=top= / =/*= は **throw** → ガード必須。url() 内セミコロン対応は 2026-07 に修正済み
- style-to-js は camelCase 層（CUSTOM_PROPERTY_REGEX で =--x= 保護、reactCompat で vendor prefix 処理）— komeiji では採用せず自前 12 行 camelize（throw ガード + lowercase + custom prop 保護を統合するため）
- satori-html の naive camelize: custom property 保護なし（=--x= → =-X= 腐敗、実証 3 重確認）、-ms 特例なし
- 手書き split(';') の失敗例: cheerio#5410（data URI）、svelte#9637、reworkcss/css#67/#137。正しい手書きは quote/paren 追跡スキャナ（nuxt og-image =splitCssDeclarations=）

* 実装案比較と選定

| 案 | 構成 | pros | cons | 判定 |
|---|---|---|---|---|
| A | ultrahtml + entities + style-to-js | direct 3、上流と同作者 | regex parser の未知リスク、decode 層自作、selector は bundled parsel（Bun 脆弱性の実績） | 次 |
| **B** | **htmlparser2 + css-select + css-what + style-to-object** | **実証済み Bun 動作、全レイヤを実績ある実装に委譲、entity 解決無料、~300 行** | transitive 10（全 micro・全現役） | **採用** |
| C | parse5 | full WHATWG | OG 画像の管理入力に対し過剰・低レベル API | 却下 |
| D | ゼロ依存ハンドロール | 0 deps | justjshtml が示す ~9k LOC、long-tail bug 再生産リスク | 却下 |
| E | himalaya / node-html-parser / linkedom | - | 実証で失格（配列 API / malformed 落下 / entity での text 分裂） | 却下 |

- direct deps は A と B で同数（3–4）。「見かけ 1 dep だが 3 lib を bundle している」A より B の方が誠実
- 配信後、css-select の =selectAll= がジェネリック（=<Node, ElementNode extends Node>=）であることを確認し、domhandler 型を排除 → src に構造的ノード型を定義 → 公開 .d.ts が完全自己完結型に

* komeiji 設計（採用案 B）

#+BEGIN_SRC text
pipeline: fmt interpolations (cooked strings!)
  → htmlparser2 parseDocument
  → <style> 抽出 + rule 分離（quote/brace スキャナ、at-rule 破棄 = 上流同じ）
  → css-select 適用（specificity 昇順 → source 順、inline attr が最終勝ち）
  → tw ヒューリスティック（TW_NAMES 移植、satori が props.tw をネイティブ消費）
  → walk → VNode（ルート div flex column 100%/100% で包む）
#+END_SRC

- children: ホールなし。単一 non-empty text 子 → string。satori normalizeChildren 後はレンダリング等価
- style: style-to-object + 自前 camelize 12 行（throw → {} ガード、custom prop 保護、lowercase、React 流 vendor prefix =-webkit-*→Webkit*, -ms-*→ms*=）
- deviations（すべてレンダリング等価または改善、テスト固定）: entity decode ON / tag・attr lowercase / ホールなし children / =--x= 保持 / =!important= 空白保持 / Bun =strings.raw= 回避
